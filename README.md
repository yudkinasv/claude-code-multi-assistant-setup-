# Многоассистентная оргструктура в Claude Code

**Что это.** Методичка для развёртывания команды AI-ассистентов в Claude Code, которые координируются между собой через файловые каналы и интегрируются с внешними сервисами по REST API.

**Откуда это.** Собрана из реального опыта построения такой оргструктуры для бренда «Паломница» (швейное производство, владелица — один человек, ведущий три параллельных бренда). В примерах используется эта реальная команда из четырёх ассистентов, потому что конкретные иллюстрации читаются легче абстракций.

**Кому это.** Тому, кто:
- Работает с Claude Code не от случая к случаю, а живёт в нём (несколько часов в день).
- Имеет несколько параллельных проектов и хочет, чтобы один ассистент не путался между ними.
- Хочет связать Claude Code с внешним планировщиком/CRM/календарём через API.
- Готов вложить 4-8 часов в первоначальную настройку, чтобы потом получить устойчивую систему.

**Что не для всех.** Если у тебя один проект, одна задача, и Claude Code — это твоя «иногда-нужная-помощь» — оверкилл. Открой обычный чат, не строй вертикаль.

## Структура методички

Читать в порядке:

1. **[Концепция](01-concept.md)** — что такое многоассистентная оргструктура, зачем она нужна, какие принципы лежат в основе.

2. **[Типы ролей](02-roles.md)** — какие бывают ассистенты в команде (координатор, инфраструктурщик, специалист, писатель), как они разделяются.

3. **[Инфраструктура](03-infrastructure.md)** — папки на диске, git-репозитории, worktree-ветки, профили терминала, memory.

4. **[Каналы коммуникации](04-channels.md)** — как ассистенты «разговаривают» друг с другом через файлы. Триггеры записи, автопроверка при старте сессии.

5. **[Внешние интеграции](05-external-integration.md)** — подключение через REST API (на примере SingularityApp — заменяемо на Notion, Todoist, Trello).

6. **[Регулярные проверки](06-recurring-tasks.md)** — задачи, которые ассистент должен выполнять с определённой периодичностью (мониторинг нагрузки, проверка состояния).

7. **[Грабли](07-pitfalls.md)** — выученные на собственной шкуре: что делает Code не так, как ожидается; обходы.

8. **[Чек-лист запуска](08-checklist.md)** — пошаговый recipe «развернуть с нуля за 4 часа».

В папке `templates/` — шаблонные файлы (CLAUDE.md, инструкции ролей, channel-файлы, settings.local.json и т.д.), готовые к заполнению.

В папке `examples/` — реальные роли из команды Паломницы, с пояснениями.

## Два способа использовать методичку

### A. Прочесть и сделать самому

1. Прочти [01-concept.md](01-concept.md) — пять минут, чтобы понять что вообще ты строишь.
2. Прочти [08-checklist.md](08-checklist.md) — конкретные шаги.
3. По мере исполнения шагов — открывай нужные разделы (03, 04, 05) для деталей.
4. На граблях ([07-pitfalls.md](07-pitfalls.md)) — глянь до того, как начнёшь.

### B. Делегировать своему Claude Code

Открой [**AGENT-PROMPT.md**](AGENT-PROMPT.md) и следуй инструкциям: склонируй репо, запусти `claude` в этой папке, скопируй стартовый промпт в первое сообщение. Code прочитает методичку, представится и начнёт интервью. Дальше — за 2-4 часа диалога он соберёт оргструктуру, останавливаясь на шагах, которые требуют тебя (создание репо на GitHub, получение токенов, 2FA).

Этот способ не «быстрее» по часам, но **не требует читать методичку самому** — твой Code прочитает за тебя и проведёт по шагам.

## Что эта методичка не покрывает

- **Не основы Claude Code.** Предполагается, что ты уже умеешь запускать `claude` в терминале, делать `/exit`, копировать промпты. Если нет — сначала [официальная документация Claude Code](https://docs.claude.com/claude-code).
- **Не основы git.** Если не знаешь что такое коммит и push — этой методички не хватит, нужны другие материалы.
- **Не как писать промпты.** Этот вопрос покрыт массой других источников.
- **Не выбор инструментов.** Я не сравниваю Code с Cursor, Replit, и т.д. Если ты выбрал Code — методичка ускоряет работу с ним.
