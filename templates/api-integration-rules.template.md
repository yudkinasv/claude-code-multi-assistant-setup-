# Шаблон раздела «Интеграция с <сервис>» для CLAUDE.md координатора

Этот блок вставляется в CLAUDE.md координатор-ассистента. Описывает все триггеры и процедуры работы с внешним API.

Перед использованием — заменить плейсхолдеры в `<угловых скобках>`.

---

## <N>. Интеграция с <сервис>

### <N>.1. Токен

Токен в файле: `<путь к ассистенту>/.<сервис>-token`.

При работе с API:
1. Прочесть токен: `TOKEN=$(cat "<путь к токену>")`.
2. Использовать в заголовке: `-H "Authorization: Bearer $TOKEN"`.

Файл `.<сервис>-token` — в `.gitignore`. Никогда не комитить.

### <N>.2. Базовый URL

`<base-url, например https://api.singularity-app.com/v2>`

Default project ID (или аналогичный важный параметр): `<значение>`.

---

### <N>.3. Запись задачи / создание объекта

**Триггер** — пользователь говорит:
- «в <сервис>: <X>»
- «<короткая фраза>: <X>»
- «<синоним>: <X>»

**Действие:**
1. **Write tool** → создать файл `<путь к ассистенту>/_payload.json` с содержимым:
   ```json
   {"<основное-поле>":"<X>","<второе-поле>":"<значение>"}
   ```
2. **Bash:**
   ```bash
   TOKEN=$(cat "<путь к токену>")
   curl -s -X POST "<base-url>/<endpoint>" \
     -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" \
     --data-binary @"<путь к ассистенту>/_payload.json" \
     -w "\nHTTP: %{http_code}\n"
   ```
3. **Bash:** `rm "<путь к ассистенту>/_payload.json"`.
4. В чате: «добавил в <сервис>: <X>».

---

### <N>.4. Чтение задач / автосинхронизация

**При первом сообщении пользователя в чате** — если с последней проверки прошло больше **60 минут** (читать отметку в `status.md`):

1. **Bash:**
   ```bash
   TOKEN=$(cat "<путь к токену>")
   curl -s "<base-url>/<list-endpoint>?<filter-params>" \
     -H "Authorization: Bearer $TOKEN" \
     -o "<путь к ассистенту>/_response.json"
   ```
2. **Read** временного файла.
3. **Grep** по полям (`"checked":1`, `"timestamp"` свежее последней проверки).
4. Если есть свежевыполненные — упомянуть пользователю одной строкой:
   > «отмечено выполненным: <название задачи> — учёл».
5. Обновить в `status.md` отметку «<сервис>-синхронизация: последняя проверка — YYYY-MM-DD HH:MM».
6. Удалить `_response.json`.
7. Коммит «status: проверил <сервис>» + push.

### <N>.5. Свежая проверка по команде

**Триггер:**
- «проверь <сервис>»
- «что в <сервис>»
- «как там задачи»

**Действие:** то же что в <N>.4, но без проверки таймера — читать всегда.

### <N>.6. Закрытие задачи

**Триггер:**
- «готово: <X>»
- «закрой задачу <X>»
- «отметь выполненной: <X>»

**Действие:**
1. GET список задач (как в <N>.4).
2. Найти задачу с названием содержащим `<X>`.
3. Если совпадение однозначное — PATCH:
   ```bash
   curl -s -X PATCH "<base-url>/<endpoint>/<id>" \
     -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"checked":1}' \
     -w "\nHTTP: %{http_code}\n"
   ```
4. Если совпадений несколько — переспросить пользователю.
5. В чате: «отметил выполненной: <название>».

---

### <N>.7. Что НЕ делать

- НЕ использовать `python3` для парсинга JSON (на Windows открывает MS Store).
- НЕ использовать heredoc с JSON-телом в bash (Code просит подтверждение на brace-обфускацию даже при allow-list).
- НЕ комитить токен в git, даже в приватный репо.
- НЕ делать DELETE без явной команды пользователя.
