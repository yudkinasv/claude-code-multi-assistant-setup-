# Регулярные проверки Архипа

Список задач, которые я (Архип) должен периодически проверять. При первом сообщении Светланы в каждой моей сессии — посмотреть этот файл, выделить просроченные, упомянуть Светлане в начале ответа.

**Формат записи:**
```
## <название>
- **Периодичность:** ежедневно / еженедельно / ежемесячно / разово к дате
- **Последняя проверка:** YYYY-MM-DD
- **Следующая проверка не позже:** YYYY-MM-DD
- **Что делать:** короткое описание процедуры
- **Что докладывать Светлане:** какой результат должен прийти к ней
```

После проверки — обновить дату «Последняя проверка» и пересчитать «Следующая проверка не позже».

## Нагрузка Singularity-интеграции Костика

- **Периодичность:** еженедельно
- **Последняя проверка:** 2026-05-14
- **Следующая проверка не позже:** 2026-05-21
- **Что делать:**
  1. GET `/v2/task?projectId=<DEFAULT_PROJECT_ID>&maxCount=500` — посчитать общее количество задач в проекте.
  2. Оценить размер JSON-ответа (через `wc -c` на сохранённом файле).
  3. Прикинуть текущую нагрузку: число задач × частота заходов × текущий интервал автопроверки.
  4. Сверить с прошлой неделей — растёт ли число задач.
- **Когда поднимать тревогу:**
  - Задач в проекте больше 50 — JSON-ответ становится тяжёлым (>30 КБ), стоит обсудить увеличение интервала или фильтрацию.
  - Заходы становятся очень частыми (5+ автопроверок в день) — обсудить ослабление частоты.
  - В API Singularity изменилось что-то (поля, лимиты) — пересобрать шаблон.
- **Что докладывать Светлане:** одной фразой — «нагрузка интеграции Singularity: X задач, ~Y КБ JSON, нагрузка в норме / на грани / нужна оптимизация».
