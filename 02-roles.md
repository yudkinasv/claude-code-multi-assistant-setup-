# 2. Типы ролей

В многоассистентной оргструктуре каждый ассистент попадает в одну из четырёх архетипических ролей. Это не догма — на практике могут быть гибриды и подвиды, но базовая карта именно такая.

---

## Координатор

**Один на всю систему.** Если в команде больше одного координатора — это уже не координатор, а помощники, и узкое место (твоё время) разваливается на две точки решений.

**Что делает:**
- Видит **все проекты** (бренды/направления/клиенты) сразу.
- Собирает прикладной план реализации по шагам.
- Сопровождает тебя по плану: где сейчас, что разблокировалось, что упёрлось.
- Координирует других ассистентов: «передай X», «попроси Y сделать Z».
- Интегрирован с внешним планировщиком (Singularity, Notion, Todoist) — пишет туда задачи и читает статусы.

**Чего не делает:**
- Не пишет содержательные тексты (это писатель/копирайтер).
- Не принимает архитектурные решения (это ты).
- Не работает с визуалом (это дизайнер/визуал-стратег).
- Не лезет в специфические зоны (бренд, юридика, продакшен).

**Где живёт:** в собственном репозитории, не привязан к репо конкретного проекта. Это важно — координатор должен быть «над» проектами, не «внутри» одного из них. Если живёт внутри одного проекта — теряет нейтральность.

**Реальный пример в команде Паломницы:** Костик. Папка `E:\КЛОД\костик\`. Один помощник на три параллельных бренда (Паломница, Юбкина, Трикотаж). У него двусторонний канал к каждому ассистенту-специалисту, интеграция с SingularityApp через API.

---

## Инфраструктурщик / Мастер

**Один или несколько.** В небольшой команде — один. Может потом разделиться (например, на «по серверам» и «по локальной среде»).

**Что делает:**
- Создаёт и поддерживает инфраструктуру: репозитории, worktree, профили терминала.
- Подключает новых ассистентов: готовит CLAUDE.md, инструкцию, handover, memory, профиль.
- Помогает с техническими задачами, не привязанными к содержанию (миграции, переезды, разруливание команд PowerShell/bash, вход в GitHub, настройка 2FA).
- Координирует архитектуру параллельных сессий: что где живёт, не пересекаются ли файлы.

**Чего не делает:**
- Не пересматривает якоря проектов.
- Не пишет финальные тексты.
- Не подменяет координатора (не ведёт план работы) и не подменяет писателя (не сочиняет).

**Где живёт:** свой репозиторий, как и координатор. Тоже «над» проектами.

**Реальный пример:** Архип. Папка `E:\КЛОД\архип\`. Делает инфраструктурную работу для всех брендов сразу. Заводит новых ассистентов (как Глеба для Паломницы), настраивает профили терминала, работает с GitHub. Имеет регулярные проверки (`recurring-tasks.md`) — например, раз в неделю проверяет нагрузку API-интеграции.

---

## Специалист / Менеджер направления

**Несколько, по одному на узкую зону.** В команде их обычно 1-3. С ростом проекта может появляться больше.

**Что делает:**
- Работает в **узкой зоне** одного проекта (бренд-менеджмент, юридика, конкретная функция).
- Готовит ТЗ для творческих подрядчиков (в т.ч. для других ИИ-ассистентов или внешних людей).
- Принимает результаты, оценивает соответствие методологии своей зоны.
- Удерживает рамки и якоря этой зоны между итерациями.

**Чего не делает:**
- Не пересматривает архитектуру проекта (это решение владельца).
- Не пишет финальные творческие тексты (это писатель/стратег).
- Не координирует другие направления (это координатор).

**Где живёт:** обычно в worktree-ветке репо проекта (потому что ему нужен доступ ко всем документам проекта). Своя ветка нужна, чтобы не путать его наработки с основной веткой.

**Реальный пример:** Глеб — бренд-менеджер Паломницы. Папка `E:\КЛОД\паломница-brand-manager\`, ветка `brand-manager`. Видит всё репо Паломницы (концепция, архитектура, оргструктура, тон голоса). Готовит брифы для бренд-стратега, оценивает результаты, удерживает якоря бренда.

---

## Писатель / Стратег / Творческий специалист

**Несколько, по одному на жанр.** Слоганист — один. Копирайтер — другой. Визуал-стратег — третий. Шеф-редактор контента — четвёртый. Все они **разные** — слоганист не пишет статью, копирайтер не подбирает шрифт.

**Что делает:**
- Производит **финальные текстовые/визуальные артефакты** по своему жанру.
- Опирается на бриф, который ему дал менеджер направления.
- Возвращает варианты, обсуждает с тобой, дотачивает по обратной связи.

**Чего не делает:**
- Не пересматривает архитектуру и якоря (этим управляет менеджер).
- Не выходит за свой жанр (слоганист — короткие фразы, не длинные тексты).
- Не отправляет финальный результат «в продакшен» сам — финализирует ты.

**Где живёт:** обычно тоже в worktree-ветке проекта, отдельной от менеджера. Свою ветку — чтобы черновики и итерации не лезли в основную работу. Когда что-то готово к финализации — соответствующий артефакт мерж-ится в основную ветку через тебя.

**Реальный пример (планируется в команде Паломницы):**
- Лариса — творческий бренд-стратег (слоганы, формулировки имени, заголовки разделов).
- Зарина — бренд-стратег по визуалу (палитра, шрифтовые пары, описание визуального кода).
- Корней — писатель карточек мест для раздела «Маршруты» (длинные исторические тексты).

Они не конкурируют — у каждого свой жанр.

## Как роли соотносятся

```
                    ТЫ (финальное решение)
                          ↑
                     КООРДИНАТОР  ←→  внешний планировщик (API)
                     ↙    ↓    ↘
        ИНФРАСТРУКТУРЩИК  МЕНЕДЖЕР 1   МЕНЕДЖЕР 2
                          ↓             ↓
                     СПЕЦИАЛИСТ 1A   СПЕЦИАЛИСТ 2A
                     СПЕЦИАЛИСТ 1B   СПЕЦИАЛИСТ 2B
```

- **Вертикаль решений** — от тебя вниз. Координатор и менеджеры — это твои «руки», специалисты — их «руки».
- **Горизонталь коммуникации** — между ассистентами одного уровня. Например, инфраструктурщик и координатор могут обмениваться сообщениями (через каналы), если нужно завести новую инфраструктуру под новую координационную задачу.
- **Связь с внешним миром** идёт через одну точку — координатора. Это уменьшает количество интеграций и точек риска.

---

## Гибриды и подвиды

На практике границы размываются:

- **Координатор-инфраструктурщик** — в маленькой команде (1-2 ассистента) это может быть один ассистент. Не идеально, но рабочий стартовый вариант.

- **Менеджер-специалист** — если у тебя в направлении мало работы, менеджер может сам писать тексты. Когда работы становится больше — разделяй.

- **Куратор без специализации** — отдельная роль для разбора накопившихся документов, написания саммари длинных переписок, наведения порядка в бэклогах. Не координатор (он не управляет планом), не специалист (не привязан к одному направлению). Может появиться по мере роста команды.

В шаблонной системе из методички — четыре базовых роли. Гибриды разворачиваются из них объединением правил.
