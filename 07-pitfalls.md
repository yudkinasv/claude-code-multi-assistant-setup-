# 7. Грабли

Выученное на собственной шкуре. Этого нет в документации Claude Code, потому что это краевые случаи интенсивного использования. Прочти **до** того, как начнёшь — сэкономишь часы.

---

## 7.1. `claude -c` в пустой папке в интерактивном режиме

**Проблема.** В профиле терминала я пропишу `claude -c` (continue last conversation) — кажется удобным. Но если в папке ассистента ещё не было ни одной сессии (первый запуск), Code выдаёт сообщение `No conversation found to continue` и **не запускает новую сессию**. Окно ждёт ввода в обычном PowerShell.

**Когда срабатывает.** Только в интерактивном режиме (`claude -c` без `--print`). Если запустить через `claude -c --print "hello"` — там Code сам стартует новую сессию.

**Обход.** При первом запуске нового ассистента — набрать в PowerShell `claude` (без `-c`). После первой завершённой сессии в папке появляется jsonl-файл, и со следующего запуска `claude -c` работает штатно.

**Как этого избежать в инструкции пользователю.** В инструкции по запуску нового ассистента явно написать:
> «В **первый раз** в PowerShell наберите `claude` (без флага). Со второго раза профиль с `claude -c` будет работать сам».

---

## 7.2. Continuation чата не пересекает границы папок

**Проблема.** `claude -c` подхватывает **последнюю сессию в текущей рабочей папке**. У каждой папки — свой projectId, своя история. Если ты работала с ассистентом в одной папке и переехала его в другую — старая переписка осталась в прежнем месте, в новой папке Code стартует с нуля.

**Когда срабатывает.** Переезды ассистента из worktree в свой репо, переименование папок, миграция со старого диска на новый.

**Что переносится при переезде:**
- Memory (если скопировать вручную в новую projectId-папку).
- Файлы репо (через git push/clone).
- Инструкция в CLAUDE.md.

**Что НЕ переносится автоматически:**
- История чата в jsonl-файле сессии. Можно скопировать вручную, но к Code это не подцепится через `claude -c` — он не считает их «той же сессией».

**Обход.** Перед переездом — сохранить ключевые наработки сессии в файлы репо (handover, заметки в `docs/`). После переезда — новая сессия читает их и понимает контекст. Это работает лучше, чем пытаться сохранить именно чат-историю.

## 7.3. Brace-обфускация в Bash heredoc

**Проблема.** Если в Bash-команде есть `{"key":"value"}` в heredoc или inline (например, для POST-запроса с JSON-телом) — Code распознаёт это как «expansion obfuscation» и просит подтверждения у пользователя, **даже если у тебя есть `Bash(curl:*)` в allow-list**. Эвристика безопасности перекрывает allow-list.

**Когда срабатывает.** POST-запросы к внешним API через `curl -d '{...}'` или `cat <<EOF\n{...}\nEOF`.

**Обход.** Не использовать heredoc или inline JSON в Bash. Вместо этого:
1. **Write tool** создаёт файл с JSON-содержимым (Code не считает Write обфускацией).
2. **Bash** делает `curl ... --data-binary @"<путь-к-файлу>"`. В Bash-команде нет brace.
3. **Bash** делает `rm` файла после.

Это работает чисто, без подтверждений.

## 7.4. Python3 на Windows через WindowsApps

**Проблема.** На Windows команда `python3` (и `python`) часто указывает на launcher Microsoft Store. При вызове — открывает окно установки Python в Store, а не выполняет скрипт.

**Когда срабатывает.** Ассистент решает «давай я разберу этот JSON через python» — это естественное решение для парсинга, особенно если ассистент привык к Mac/Linux. На Windows это упирается в проблему.

**Обход.** Прописать в инструкциях ассистентов:
> «Python3 на Windows не использовать. Парсить JSON через `cp` + Read + текстовый grep».

И дать пример процедуры:
```bash
# Сохранить ответ API во временный файл
curl -s ... > /tmp/data.json
# Скопировать в свою рабочую папку (Read tool требует определённых разрешений)
cp /tmp/data.json E:/КЛОД/<своя-папка>/_data.json
```

Затем через Read прочесть файл, найти нужные поля через grep по тексту. Это менее изящно чем `json.load()`, но **работает надёжно** на Windows.

## 7.5. Удаление worktree с активной сессией

**Проблема.** При `git worktree remove <путь>` git снимает запись из своего реестра, но **физически папку не удаляет**, если в ней запущен какой-то процесс (в нашем случае — сессия Claude Code). Windows блокирует удаление активных файлов.

**Что получаешь:** запись о worktree снята, но папка лежит на диске. При попытке создать worktree по тому же пути — конфликт.

**Обход.**
1. **До удаления** — закрыть сессию Claude Code в этом worktree (`/exit` + закрытие вкладки).
2. **После** — `git worktree remove` снимает запись.
3. **Затем** — `rm -rf <папка>` физически удаляет.
4. Если **на следующий старт** ассистент должен быть в новой папке — поправить профиль терминала на новый путь.

## 7.6. Размер JSON в контексте ассистента

**Проблема.** Когда ассистент делает GET к большому списку (например, 100+ задач) и читает ответ через Read — JSON может быть 30-50+ КБ. Это сразу 10-15 тысяч токенов в его контекст. Если ассистент делает такие проверки часто — расход быстро растёт.

**Когда срабатывает.** Регулярные проверки канала, периодические синхронизации с API.

**Обход.**
1. **Фильтровать на стороне API**, если сервис поддерживает (например, по дате модификации, по статусу).
2. **Парсить грубо**, не читать целиком — `grep -oE '"id":"X"[^}]*"checked":[01]'` достаёт только нужные поля без всей структуры.
3. **Реже** делать проверки. Увеличить интервал автопроверки.
4. **Минимальный maxCount** в запросе (если API поддерживает).

## 7.7. Allow-list матчится по началу команды

**Проблема.** Шаблон `Bash(curl:*)` ловит команды, где `curl` — **первое слово**. Но Костик часто начинает Bash с `TOKEN=$(cat ...)`, и тогда **первое слово — `TOKEN=...`**, не `curl`. Allow-list не срабатывает, Code просит подтверждения на всю multi-line команду.

**Обход.**
1. **Перечислить все потенциальные первые команды** в allow-list: `Bash(cat:*)`, `Bash(curl:*)`, и т.п.
2. Или дать **широкий шаблон** `Bash(*)` — но это разрешает абсолютно всё. Безопасный только для специалистов в worktree-ветке, где они не могут навредить.
3. Альтернатива — **разделить на два Bash-вызова** в правилах ассистента:
   - Первый вызов: `TOKEN=$(cat ...); echo $TOKEN > /tmp/.t`.
   - Второй вызов: `curl ... -H "Authorization: Bearer $(cat /tmp/.t)"`.
   - Но это уродливо, см. опасности с токеном в файле.

В реальной системе Паломницы выбран **широкий список разрешений** (`Bash(cat:*)`, `Bash(curl:*)`, `Bash(grep:*)`, и т.п.) — точечно по конкретным командам, не широкое `Bash(*)`.

## 7.8. Memory нового projectId — Code создаёт пустую папку при первом старте

**Проблема.** Если ассистент впервые запускается в новой папке, Code создаёт папку memory под её projectId с пустым содержимым (только индекс MEMORY.md). Если ты хотела чтобы ассистент при первом запуске **уже знал** какие-то правила/контекст — он их не увидит.

**Обход.** Положить memory **до первого запуска** в предсказанную projectId-папку. Алгоритм имени projectId (упрощённо):
- Латинские буквы и цифры в пути — сохраняются.
- Дефисы — сохраняются.
- Всё остальное (двоеточия, слэши, кириллица) — заменяется на дефис.

Например, для папки `E:\КЛОД\костик\` projectId будет `E-------------` (E + 13 дефисов).

**Точную проверку** — после первого запуска посмотреть, какая папка появилась в `C:\Users\<user>\.claude\projects\`. Если расчёт совпал — memory подхватилась.

## 7.9. Active session worktree удерживает CLAUDE.md в памяти

**Проблема.** Если ассистент работает в активной сессии, а ты в это время правишь его CLAUDE.md из другой сессии — он **не подхватит** изменения автоматически. Code загружает CLAUDE.md при старте сессии.

**Обход.** Чтобы ассистент подхватил новые правила:
- **Перезапустить вкладку** (`/exit` → закрыть → открыть заново).
- **Или** в активной сессии сказать ему: «прочти свой CLAUDE.md заново, особенно раздел X». Он перечитает (Read), и в этой сессии новые правила сработают. На следующем рестарте Code сам подгрузит обновления.

## 7.10. Push после каждого коммита — обязателен для offsite-бэкапа

**Проблема.** Если делаешь много локальных коммитов без push — диск может полететь, и работа исчезнет.

**Обход.** В правилах **каждого** ассистента: «после каждого значимого коммита — `git push`». Не каждые 5 коммитов, не «вечером». **После каждого**.

Если push не прошёл (нет сети, не в логине, конфликт) — ассистент должен сообщить пользователю и **не делать вид, что бэкап есть**. Локальный коммит без push = риск потери при сбое диска.

## 7.11. Recovery-коды GitHub и токены — на бумагу

**Проблема.** 2FA на GitHub — обязательная штука. Но если потерять телефон с приложением-аутентификатором, восстановить доступ можно только через recovery-коды, которые показывают **один раз** при включении 2FA.

**Обход.** При включении 2FA:
1. Установить приложение-аутентификатор (Microsoft Authenticator, Google Authenticator, и т.п.).
2. Сразу сохранить recovery-коды (их 10-16 одноразовых строк) — **распечатать или записать на бумаге**, положить в надёжное место.
3. **Не хранить recovery-коды в файле на компьютере** — если комп сломается одновременно с телефоном, доступ потерян.

---

## 7.12. Стартовый промпт — копировать целиком, не пересказывать

**Проблема.** Стартовый промпт ассистенту — это **точные инструкции** что прочитать и в каком порядке. Если пересказать своими словами или сократить — ассистент может пропустить важные файлы, не загрузить контекст, начать «гадать с нуля».

**Обход.** Хранить стартовый промпт в файле репо ассистента (например, `docs/handover-launch.md`), и при каждом запуске **копировать его целиком** в первое сообщение. Не редактировать, не сокращать.

Если состав файлов поменялся — обновить файл со стартовым промптом, и впредь использовать новую версию.

---

## 7.13. Имена ассистентов — не упускать `tabTitle` + `suppressApplicationTitle`

**Проблема.** В Windows Terminal по умолчанию заголовок вкладки задаёт **приложение в ней** (Claude Code пишет «Claude Code» или путь к папке). Имя профиля показывается только в выпадашке «+», но не на вкладке.

**Обход.** В каждом профиле в `settings.json`:
- `"tabTitle": "<имя>"` — явно задать имя.
- `"suppressApplicationTitle": true` — запретить приложению (Claude Code) перезаписывать.

После этого имя «Костик-ассистент» будет видно на вкладке всё время.
